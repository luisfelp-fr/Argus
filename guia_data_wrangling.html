Como usar este guia

O que é Data Wrangling? É o trabalho de pegar dados "crus" (bagunçados, com nomes ruins, valores faltando, formatos errados) e deixá-los limpos e organizados para análise. Na prática, é onde um cientista de dados passa 70–80% do tempo — por isso vale dominar bem esta etapa.

🧠 Analogia: pense num DataFrame como uma planilha do Excel: cada linha é uma observação (um estudante, um cliente, um jogo) e cada coluna é uma variável (nome, tempo, distância). O pandas é o conjunto de ferramentas para mexer nessa planilha escrevendo código em vez de clicando.

Usaremos o mesmo dataset da sua aula: estudantes e o trajeto deles até a escola. Uma amostra (valores ilustrativos):

Gustavo43284Manhãagressivo

✅ Sobre os nomes no código: aqui o DataFrame principal se chama df — é a convenção universal do mercado (abreviação de DataFrame). Quando criamos versões novas, usamos nomes que dizem o que aconteceu: df_renomeado, df_filtrado, df_completo. Ler o código deve ser quase como ler uma frase em inglês.
01

Preparando o ambiente

Antes de mexer nos dados, precisamos trazer as "caixas de ferramentas" (pacotes) e carregar o arquivo.

import pandas as pd    # manipulação de tabelas (DataFrames)
import numpy as np     # cálculos numéricos e condições

# Carregando a planilha para dentro do Python
df = pd.read_excel('(1.2) dataset_principal.xls')
import pandas as pd — por que o "as pd"?
É um apelido. Em vez de escrever pandas.read_excel(...) toda vez, escrevemos pd.read_excel(...). Todo mundo no mundo usa pd para pandas e np para numpy — se você usar outro apelido, seu código vai confundir os outros (e você mesmo).
pd.read_excel('arquivo.xls') — o que acontece aqui?
O pandas abre o Excel, lê a primeira aba e devolve um DataFrame, que guardamos na variável df. O arquivo precisa estar na mesma pasta do seu script (ou você passa o caminho completo). Para arquivos .csv, o equivalente é pd.read_csv().
pd.set_option("display.max.columns", None) — para que serve?
Por padrão, o console esconde colunas quando a tabela é larga (mostra ... no meio). Essa linha diz: "mostre todas as colunas, sem limite" (None = sem limite). É só uma configuração de exibição — não muda seus dados em nada.
⚠️ Erro clássico de iniciante: FileNotFoundError. No Spyder, confira se a "pasta de trabalho" (canto superior direito) é a mesma pasta onde está o arquivo Excel.
02

Espiando os dados — head, tail, info

Primeira regra do Data Wrangling: nunca mexa no que você ainda não olhou. Estes comandos são o seu "reconhecimento do terreno".

df.head(n=5)     # as 5 primeiras linhas
df.tail(n=3)     # as 3 últimas linhas
df.columns       # só os nomes das colunas
df.info()        # raio-x completo: tipos, nulos, memória
df.shape         # (linhas, colunas) — bônus útil!
head(n=5) — por que só as primeiras linhas?
Um dataset real pode ter milhões de linhas — imprimir tudo travaria o console. head() mostra uma amostra do topo, suficiente para ver se as colunas e valores fazem sentido. O n= controla quantas linhas (o padrão já é 5, então df.head() sozinho funciona igual).
info() — o comando mais importante desta seção
Mostra, para cada coluna: o nome, quantos valores não-nulos existem (se for menor que o total de linhas, há dados faltando!) e o tipo:

• object → texto
• int64 / float64 → números (inteiro / decimal)
• category → categorias (qualitativa)

Tipo errado é a causa nº 1 de erro em análise: um número lido como texto não soma, não tira média, nada.
🧠 Analogia: head() é abrir a caixa de mudança e olhar os primeiros itens por cima. info() é a etiqueta da caixa: diz o que tem dentro, quanto tem, e se falta alguma coisa.
03

Renomeando colunas — .rename()

Colunas com espaços, acentos e parênteses ("Tempo para chegar à escola (minutos)") são um pesadelo para programar. Primeiro passo de qualquer projeto: nomes curtos, minúsculos, sem acento.

df = df.rename(columns={
    'Estudante': 'estudante',
    'Tempo para chegar à escola (minutos)': 'tempo',
    'Distância percorrida até a escola (quilômetros)': 'distancia',
    'Quantidade de semáforos': 'semaforos',
    'Período do dia': 'periodo',
    'Perfil ao volante': 'perfil'
})
columns={'nome antigo': 'nome novo'} — o dicionário de troca
É uma lista de pares "de → para". A chave (esquerda) é o nome atual; o valor (direita) é o nome novo. Você não precisa renomear todas — só as que quiser. Se errar o nome antigo, o pandas simplesmente ignora em silêncio (não dá erro!), então confira o resultado.
df = df.rename(...) — por que o "df =" no começo?
O rename não altera o DataFrame original — ele devolve uma cópia renomeada. Se você não guardar essa cópia em algum lugar, ela evapora. O df = diz: "substitua o antigo pela versão nova".
inplace=True — e essa alternativa que o professor mostrou?
df.rename(..., inplace=True) altera o original direto, sem precisar do df =.

🧠 Analogia: df = df.rename(...) é fazer uma fotocópia corrigida e jogar fora a antiga. inplace=True é rasurar o documento original com caneta.

✅ Prática de mercado: prefira df = df.rename(...). O inplace está caindo em desuso (o time do pandas desaconselha e planeja removê-lo) e o padrão de reatribuição funciona igual em todos os métodos.

04

Selecionando colunas e linhas

Quase tudo no pandas começa com "pegue este pedaço da tabela". Há duas formas: pelo nome (mais comum) e pela posição (iloc).

Pelo nome — o jeito do dia a dia

# Uma coluna (repare: 1 par de colchetes)
serie_tempo = df['tempo']

# Várias colunas (repare: 2 pares — é uma LISTA dentro dos colchetes)
df_resumido = df[['tempo', 'perfil']]
Por que às vezes [ ] e às vezes [[ ]]?
df['tempo'] pede uma coluna e devolve uma Series (uma coluna solta). df[['tempo', 'perfil']] passa uma lista de nomes — o colchete de fora é o "pegue", o de dentro é a lista — e devolve um DataFrame (mini-tabela).

🧠 Analogia: pedir 1 item da prateleira vs. entregar uma listinha de compras com vários itens.
df.perfil — o atalho com ponto
Funciona igual a df['perfil'], mas só quando o nome da coluna não tem espaço, acento ou conflito com métodos do pandas. Prefira os colchetes: funcionam sempre.

Pela posição — .iloc[linhas, colunas]

df.iloc[3, :]      # linha na posição 3, todas as colunas
df.iloc[:, 4]      # todas as linhas, coluna na posição 4
df.iloc[2:5, :]    # linhas 2, 3 e 4  (o 5 fica DE FORA!)
df.iloc[2:4, 3:5]  # linhas 2-3 e colunas 3-4
O : sozinho — o que significa?
Significa "tudo". df.iloc[:, 4] lê-se: "todas as linhas (:), coluna de posição 4". O primeiro espaço é sempre das linhas, o segundo das colunas.
Por que 2:5 pega só 2, 3 e 4? E por que começa do zero?
Duas regras do Python que valem para tudo:
1. Contagem começa em 0 — a primeira linha é a posição 0.
2. Em intervalos a:b, o início entra e o fim fica de fora.

🧠 Analogia: é como andar de elevador na Europa: o "térreo" é o andar 0. E o intervalo 2:5 é "do andar 2 até antes do 5".
loc vs iloc — qual a diferença?
iloc = integer location → busca por posição numérica (0, 1, 2...).
loc = location → busca por rótulo/nome (nome da coluna, valor do índice) e aceita condições.
Exemplo com loc: df.loc[:, df.columns.str.startswith('per')] pega todas as colunas cujo nome começa com "per" (pegaria periodo e perfil). Existe também str.endswith('o') para o final do nome.
05

Criando e transformando colunas

O feijão com arroz do wrangling: criar uma coluna nova a partir de outras, ou traduzir os valores de uma coluna.

Coluna calculada a partir de outras

# Semáforos por quilômetro, arredondado para 2 casas decimais
df['semaforos_por_km'] = round(df['semaforos'] / df['distancia'], 2)
Como isso funciona linha a linha sem eu escrever um loop?
O pandas é vetorizado: quando você divide duas colunas, ele divide cada linha pela linha correspondente, automaticamente. É como aplicar uma fórmula do Excel na coluna inteira de uma vez, em vez de célula por célula.
round(valor, 2)
Arredonda para 2 casas decimais. O segundo argumento é o número de casas — round(x, 0) arredondaria para inteiro.

Traduzindo valores — .map() com dicionário

# O dicionário é a "tabela de tradução": de → para
traducao_perfil = {'calmo': 'perfil_A',
                   'moderado': 'perfil_B',
                   'agressivo': 'perfil_C'}

df['perfil_codigo'] = df['perfil'].map(traducao_perfil)
.map(dicionario) — o que ele faz exatamente?
Percorre a coluna e, para cada valor, procura no dicionário e substitui pela tradução. "calmo" → acha a chave "calmo" → devolve "perfil_A".

⚠️ Se um valor não estiver no dicionário, ele vira NaN (vazio) — não dá erro. Sempre confira depois com df['perfil_codigo'].isna().sum().
E o .assign() que o professor usou?
df_novo = df.assign(perfil_codigo = df['perfil'].map(traducao_perfil)) faz a mesma coisa, mas devolve um DataFrame novo em vez de alterar o atual. É muito usado em encadeamentos (seção 16). Regra prática: coluna avulsa → df['nova'] =; dentro de uma corrente de operações → .assign().
⚠️ Texto → número: cuidado com a "ponderação arbitrária"
Mapear {'calmo': 1, 'moderado': 2, 'agressivo': 3} parece inofensivo, mas números têm ordem e distância: o 3 é "3× o 1"? "Agressivo" é 3× "calmo"? Não! Se a variável é categórica, converta para o tipo category (seção 7) para o Python não fazer contas indevidas com ela.

06

Colunas condicionais — np.select e pd.qcut

"Se o tempo for até 20, é rápido; entre 20 e 40, médio; acima de 40, demorado." Categorizar por regras é uma das tarefas mais comuns — e há um jeito limpo de fazer.

condicoes = [
    df['tempo'] <= 20,
    df['tempo'] <= 40,
    df['tempo'] > 40
]
categorias = ['rápido', 'médio', 'demorado']

df['faixa'] = np.select(condicoes, categorias, default='sem_faixa')

Condições e resultados lado a lado, em listas paralelas. Lê-se de cima para baixo, como uma tabela de regras.

df['faixa'] = np.where(df['tempo'] <= 20, 'rápido',
             np.where((df['tempo'] > 20) & (df['tempo'] <= 40), 'médio',
             np.where(df['tempo'] > 40, 'demorado',
                      'demais')))

Funciona, mas cada condição extra é mais um np.where dentro do anterior — e mais um parêntese para fechar no final. Com 5+ categorias, vira um labirinto.

np.select(condicoes, categorias, default=...) — os 3 argumentos
1º: lista de condições, testadas em ordem, de cima para baixo.
2º: lista de resultados, pareada posição a posição com as condições (1ª condição verdadeira → 1º resultado).
3º: default = o valor usado se nenhuma condição for verdadeira (a "rede de segurança").

🧠 Analogia: uma triagem de hospital — o paciente passa pelas perguntas em ordem e recebe a pulseira da primeira pergunta em que se encaixar.
Por que a 2ª condição pode ser só <= 40, sem o > 20?
Porque as condições são testadas em ordem: quem tem tempo ≤ 20 já foi capturado pela 1ª condição e não chega na 2ª. Então "≤ 40", na prática, só pega quem está entre 20 e 40. Isso elimina os & e deixa o código mais curto.
np.where(condicao, se_sim, se_nao) — quando ainda usar?
Quando há só duas saídas, ele é perfeito e mais simples: df['atrasado'] = np.where(df['tempo'] > 40, 'sim', 'não'). Lê-se: "onde a condição for verdadeira, use o 1º valor; senão, o 2º". Regra de bolso: 2 saídas → np.where; 3 ou mais → np.select.

Categorizar por quartis — pd.qcut()

df['quartil_tempo'] = pd.qcut(df['tempo'], q=4, labels=['1', '2', '3', '4'])
q=4 e labels= — o que significam?
qcut ordena os valores e os divide em q grupos com a mesma quantidade de observações em cada um. Com q=4, são os quartis: os 25% menores tempos viram grupo "1", os 25% seguintes "2", e assim por diante. O labels dá nome aos grupos (sem ele, o pandas mostra os intervalos numéricos).

🧠 Analogia: uma fila de 100 pessoas por altura, cortada em 4 blocos de 25 — não importa a altura exata, importa em qual bloco você caiu.

🎯 Quiz: no np.select, um estudante com tempo = 20 recebe qual faixa?

07

Trocando tipos e excluindo colunas

Duas ferramentas de organização: dizer ao pandas o que cada coluna é (astype) e jogar fora o que não serve (drop).

# Converter para categórica (evita contas indevidas com códigos)
df['perfil_codigo'] = df['perfil_codigo'].astype('category')

# Excluir colunas que não vamos usar
df = df.drop(columns=['periodo', 'perfil'])
astype('category') — por que se importar com tipos?
Se "perfil" virou os códigos 1, 2, 3 e ficou como número, nada impede alguém de tirar a média do perfil (1.8?!) — um número sem sentido. Declarar category avisa o pandas: "isto é um rótulo, não uma quantidade". Outros valores comuns: astype(int), astype(float), astype(str).
drop(columns=[...]) — e o famoso axis=1?
Você verá muito por aí df.drop(['periodo'], axis=1). O axis diz a direção da operação:

• axis=0 → opera nas linhas (direção vertical, de cima para baixo)
• axis=1 → opera nas colunas (direção horizontal)

🧠 Analogia: num prédio, axis=0 é o elevador (percorre andares/linhas) e axis=1 é o corredor (percorre salas/colunas).

✅ Escrever columns=[...] dispensa decorar o axis — o código diz sozinho o que faz. É a forma recomendada hoje.
08

Adicionando linhas — pd.concat()

Chegou um estudante novo depois da coleta? concat empilha DataFrames um embaixo do outro.

novo_estudante = pd.DataFrame({'estudante': ['Roberto'],
                               'tempo': [40],
                               'periodo': ['Tarde']})

df_completo = pd.concat([df, novo_estudante]).reset_index(drop=True)
pd.concat([df, novo_estudante]) — como ele sabe onde encaixar?
Ele alinha pelo nome das colunas, mesmo que estejam em ordem diferente. Colunas que o novo registro não tem (distancia, semaforos...) são preenchidas com NaN (valor faltante) — o pandas não inventa dados. Repare que o argumento é uma lista [df, novo]: você pode empilhar 2, 3, 10 DataFrames de uma vez.
.reset_index(drop=True) — por que sempre aparece depois?
Cada linha tem um número de identificação (o índice). Ao empilhar, os números vêm junto: seu df termina no índice 9 e o Roberto chega com índice 0 — ficando dois "0" na tabela! reset_index() renumera tudo do zero (0, 1, 2...).

E o drop=True? Sem ele, o pandas guarda a numeração antiga como uma coluna nova chamada "index" (tralha). Com drop=True, ele joga a numeração antiga fora.

🧠 Analogia: renumerar as páginas de dois cadernos colados — o drop=True é apagar os números antigos em vez de deixá-los rabiscados na margem.
09

Ordenando — .sort_values()

Colocar as linhas em ordem por uma ou mais colunas — como o "Classificar" do Excel.

# Do menor para o maior tempo
df_por_tempo = df.sort_values(by='tempo', ascending=True).reset_index(drop=True)

# Dois critérios: perfil de Z→A e, dentro de cada perfil, distância de menor→maior
df_ordenado = df.sort_values(by=['perfil', 'distancia'],
                             ascending=[False, True]).reset_index(drop=True)
by= — o critério de ordenação
Qual(is) coluna(s) mandam na ordem. Com uma lista by=['perfil', 'distancia'], o pandas ordena pelo 1º critério e usa o 2º como desempate — igual ordenar uma lista telefônica por sobrenome e depois por nome. Funciona com texto também (ordem alfabética).
ascending= — a direção
True = crescente (A→Z, menor→maior); False = decrescente. Com vários critérios, passe uma lista pareada: ascending=[False, True] significa "perfil decrescente, distância crescente" — cada posição casa com a coluna correspondente do by.
10

Resumindo os dados — estatísticas descritivas

Depois de limpar, é hora de conhecer os dados: médias, contagens, frequências.

df.describe()          # painel geral das colunas numéricas

df['tempo'].mean()     # média
df['tempo'].median()   # mediana (valor do meio)
df['tempo'].std()      # desvio padrão (o quanto os valores se espalham)
df['tempo'].quantile([0.25, 0.75])  # 1º e 3º quartis

df[['tempo', 'distancia', 'semaforos']].corr()  # matriz de correlações
describe() — como ler o painel
Para cada coluna numérica: count (quantos valores), mean (média), std (desvio padrão), min/max, e os percentis 25%/50%/75%. É o "check-up" de 1 linha: valores absurdos (idade = 999?) aparecem na hora no min/max.
corr() — o que significa o resultado?
Mede o quanto duas variáveis "andam juntas", de -1 a +1. Perto de +1: quando uma sobe, a outra sobe (tempo × distância, provavelmente). Perto de -1: quando uma sobe, a outra desce. Perto de 0: sem relação linear. ⚠️ Correlação não é causa!

Para variáveis de texto/categóricas

df['periodo'].value_counts()                 # contagem de cada categoria
df['perfil'].value_counts(normalize=True)    # em proporção (0.30 = 30%)

df['perfil'].unique()    # quais valores existem (lista)
df['perfil'].nunique()   # quantos valores diferentes existem (número)

pd.crosstab(df['periodo'], df['perfil'])     # tabela cruzada 2 variáveis
value_counts(normalize=True) — o que o normalize muda?
Sem ele: contagens absolutas ("Manhã: 6, Tarde: 4"). Com normalize=True: proporções ("Manhã: 0.6, Tarde: 0.4" = 60% / 40%). "Normalizar" aqui significa dividir tudo pelo total.
pd.crosstab(linhas, colunas) — para que serve?
Cruza duas variáveis qualitativas: quantos estudantes são "calmos e da manhã"? O 1º argumento vira as linhas, o 2º as colunas da tabela. Com normalize=True, mostra em proporção do total. É a "tabela dinâmica" mais simples que existe.
unique() vs nunique()
unique() lista os valores distintos (['calmo', 'moderado', 'agressivo']); nunique() só conta quantos são (3). Ótimos para achar erros de digitação: se aparecer 'calmo' e 'Calmo ', são categorias diferentes para o pandas!
11

Agrupando — .groupby() + .agg()

A dupla mais poderosa do pandas. Perguntas como "qual o tempo médio por período?" são sempre groupby + agg.

🧠 Analogia — separar, calcular, juntar: imagine separar as fichas dos estudantes em pilhas por período (Manhã, Tarde). O groupby faz as pilhas. Depois o agg calcula algo dentro de cada pilha (média, contagem...) e monta uma tabelinha com um resultado por pilha.
resumo_por_periodo = df.groupby('periodo').agg(
    tempo_medio = ('tempo', 'mean'),
    distancia_media = ('distancia', 'mean'),
    qtd_estudantes = ('estudante', 'count')
)
groupby('periodo') — o que ele devolve?
Sozinho, ele devolve um objeto "agrupado" que ainda não mostra nada útil — são só as pilhas montadas, esperando você dizer o que calcular. Por isso ele quase sempre vem seguido de .agg(), .mean(), .size() ou .describe(). Pode agrupar por mais de um critério: df.groupby(['periodo', 'perfil']) cria uma pilha para cada combinação (Manhã+calmo, Manhã+agressivo, Tarde+calmo...).
agg(nome_novo = ('coluna', 'função')) — a sintaxe nomeada
Cada linha diz: "crie a coluna nome_novo, aplicando a função na coluna". tempo_medio = ('tempo', 'mean') = "coluna tempo_medio, média da coluna tempo". Funções comuns: 'mean', 'median', 'sum', 'count', 'min', 'max', 'std'.

O professor usou o formato de dicionário agg({'tempo': 'mean'}) — também funciona, mas o formato nomeado deixa você batizar as colunas do resultado, o que fica muito mais legível.
.size() e .describe().T
df.groupby('periodo').size() conta quantas linhas há em cada grupo. describe().T gera o painel completo por grupo; o .T transpõe (gira a tabela 90°, linhas viram colunas) — só para caber melhor no console.

12

Filtrando linhas

"Quero só os estudantes calmos da tarde." Há dois estilos — os dois aparecem em provas, tutoriais e no trabalho, então vale conhecer ambos.

df.query('perfil == "calmo"')
df.query('perfil == "calmo" & periodo == "Tarde"')   # E (interseção)
df.query('perfil == "calmo" | periodo == "Tarde"')   # OU (união)
df.query('perfil != "calmo"')                        # diferente
df.query('tempo >= 25')
df.query('tempo.between(25, 40)')

A condição vai entre aspas, como uma frase. Dentro dela, textos usam o outro tipo de aspas (por isso 'perfil == "calmo"').

df[df['perfil'] == 'calmo']
df[(df['perfil'] == 'calmo') & (df['periodo'] == 'Tarde')]
df[(df['perfil'] == 'calmo') | (df['periodo'] == 'Tarde')]
df[df['perfil'] != 'calmo']
df[df['tempo'] >= 25]
df[df['tempo'].between(25, 40, inclusive='both')]

Lê-se de dentro para fora: df['perfil'] == 'calmo' gera uma coluna de True/False (a "máscara"), e o df[...] de fora guarda só as linhas True. ⚠️ Com & e |, cada condição precisa dos seus parênteses.

&, | e ~ — os três operadores lógicos
& = E (as duas condições verdadeiras) · | = OU (pelo menos uma verdadeira) · ~ = NÃO (inverte tudo: df[~(df['tempo'] >= 25)] pega quem tem tempo menor que 25).

🧠 Analogia (filtro de festa): & = "convidado e com traje social"; | = "convidado ou acompanhante"; ~ = "todo mundo exceto a lista negra".
.between(25, 40, inclusive='both')
Atalho para "entre 25 e 40". O inclusive decide se as pontas entram: 'both' (25 e 40 entram — padrão), 'neither' (nenhuma entra), 'left' (só o 25), 'right' (só o 40).
.isin(lista) — comparar com vários valores de uma vez
Em vez de (x == 'Ana') | (x == 'Júlia') | ..., faça:
nomes = ['Gabriela', 'Ana', 'Júlia']
df[df['estudante'].isin(nomes)]

"isin" = is in = "está em". Devolve True para quem está na lista. Combine com ~ para "quem NÃO está na lista".
O @ dentro do query — df.query('estudante.isin(@nomes)')
Dentro das aspas do query, o pandas só enxerga nomes de colunas. O @ é o crachá que diz: "isto não é coluna, é uma variável do meu script — busque lá fora".

Juntando bases — pd.merge()

Os dados raramente vêm numa tabela só: notas num arquivo, cadastro em outro. O merge cruza duas tabelas usando uma coluna-chave em comum.

🧠 Analogia: é o PROCV do Excel, só que profissional. A coluna "estudante" é a chave: para cada nome da tabela A, o merge busca o mesmo nome na tabela B e cola as colunas dela ao lado.
# As duas tabelas precisam da chave com o MESMO nome
df_notas = df_notas.rename(columns={'Estudante': 'estudante'})

df_completo = pd.merge(df, df_notas, how='left', on='estudante')
on='estudante' — a chave
A coluna que existe nas duas tabelas e identifica cada observação. É por ela que o pandas casa as linhas. Se os nomes forem diferentes ("Estudante" vs "estudante"), renomeie antes — para o pandas, maiúscula é outra coluna.
how= — a decisão mais importante: quem sobrevive?
Suponha: df tem Antônio (mas não Marcos) e df_notas tem Marcos (mas não Antônio).

• how='left' → ficam os estudantes da tabela da esquerda (df). Antônio fica (com nota = NaN); Marcos sai.
• how='right' → ficam os da direita. Marcos fica; Antônio sai.
• how='inner' → só quem está nas duas. Antônio e Marcos saem.
• how='outer' → todo mundo fica; o que faltar vira NaN.

🧠 Analogia (duas listas de convidados): inner = interseção (só quem está nas duas); outer = união (todo mundo); left/right = "manda quem fez a lista".
Como descobrir quem está numa base e não na outra?
df[~df['estudante'].isin(df_notas['estudante'])] — "estudantes de df que NÃO estão em df_notas". Inverta as bases para a pergunta contrária. Ótima checagem para rodar antes do merge e não ser surpreendido por NaNs.
how=Quem fica na base finalFrase para lembrar
leftTodos da esquerda"A tabela da esquerda manda"

⚠️ Antes de qualquer merge, verifique duplicatas na chave (seção 14). Se "Gabriela" aparecer 2× numa base e 3× na outra, o merge gera 6 linhas de Gabriela — e seus totais explodem sem você perceber.

Duplicatas e valores faltantes (NA)

A faxina propriamente dita: linhas repetidas e buracos na tabela.

Duplicatas — drop_duplicates()

# Quantas linhas duplicadas existem?
len(df) - len(df.drop_duplicates())      # 0 = nenhuma 🎉

# Remover duplicatas (linha inteira igual)
df_sem_duplicatas = df.drop_duplicates()

# Considerar duplicata quando SÓ estas colunas se repetem
df_sem_duplicatas = df.drop_duplicates(subset=['estudante', 'perfil'])
subset= — o que muda?
Sem subset, só é duplicata a linha 100% idêntica em todas as colunas. Com subset=['estudante', 'perfil'], basta esse par se repetir para a linha ser considerada duplicada (o pandas mantém a primeira ocorrência e descarta as demais).

Valores faltantes — isna, fillna, dropna

# Diagnóstico: quantos NAs em cada coluna?
df.isna().sum()

# Opção A: preencher os buracos
df_preenchido = df.fillna('sem_informacao')                      # texto fixo
df['tempo'] = df['tempo'].fillna(df['tempo'].mean())             # com a média ⚠️

# Opção B: excluir linhas com qualquer NA
df_sem_na = df.dropna().reset_index(drop=True)
isna().sum() — por que essa dupla?
isna() transforma a tabela em True/False (True = faltante). Como o Python conta True como 1, o .sum() soma por coluna e devolve o placar de buracos: tempo: 1, nota: 3... É sempre o primeiro comando da faxina.
fillna(valor) — preencher com o quê?
Substitui cada NaN pelo valor informado. Preencher número com a média é possível, mas ⚠️ use com muito critério (como o professor avisou): você está inventando dados, o que distorce a variância e pode enviesar a análise. A decisão certa depende do porquê de o dado faltar.
dropna() — quando excluir é ok?
Remove qualquer linha com pelo menos um NaN. Seguro quando os faltantes são poucos e aleatórios; perigoso quando são muitos (você joga fora informação) ou concentrados num grupo (você enviesa a amostra). Por isso o diagnóstico com isna().sum() vem primeiro.

Mudando o formato — pd.melt()

Às vezes a tabela está "larga" (uma coluna para cada medida) e você precisa dela "longa" (uma linha para cada medida) — principalmente para gráficos.

df_longo = pd.melt(df,
                   id_vars='estudante',
                   value_vars=['tempo', 'distancia'])
id_vars= — quem fica parado
A(s) coluna(s) de identificação, que se repetem em cada linha nova para você saber de quem é o valor. Aqui, o nome do estudante.
value_vars= — quem "derrete"
As colunas que serão empilhadas. Cada uma vira linhas, e o pandas cria duas colunas novas: variable (de qual coluna o valor veio) e value (o valor em si).

🧠 Analogia: melt = derreter. As colunas "derretem" e escorrem para baixo, empilhadas.

Encadeando funções — a linha de produção

O gran finale: como os métodos do pandas devolvem sempre um DataFrame novo, dá para emendar um no outro e ler o código como uma receita, passo a passo.

resumo = (
    df
    .assign(semaforos_por_km = round(df['semaforos'] / df['distancia'], 2))
    .query('tempo >= 30')
    .groupby('periodo')
    .agg(media_sem_por_km = ('semaforos_por_km', 'mean'),
         distancia_media = ('distancia', 'mean'),
         qtd = ('estudante', 'count'))
)

Leitura em voz alta: "pegue o df → crie a coluna semaforos_por_km → fique só com tempo ≥ 30 → agrupe por período → calcule as médias e a contagem". Cada linha é uma estação da linha de produção.

Por que os parênteses envolvendo tudo?
O Python normalmente exige que um comando caiba em uma linha. O parêntese externo diz: "isso tudo é UM comando, pode quebrar em várias linhas". Sem ele, cada quebra de linha daria erro de sintaxe. É o truque que permite o formato "receita".
Quando encadear e quando separar em etapas?
Encadeie quando os passos formam uma transformação única com nome claro (como "resumo"). Separe em variáveis intermediárias quando você precisar inspecionar o meio do caminho ou reutilizar uma etapa.
